## How to use the UART baud rate error calculator

Enter the UART's **clock frequency**, the **baud rate** you want and the **oversampling** mode. The calculator rounds to the nearest integer divisor and shows the actual baud rate and the percentage error.

## UART baud rate formulas

<p class="formula">N = round(f<sub>clk</sub> ÷ (OS × baud)) &nbsp;·&nbsp; baud<sub>actual</sub> = f<sub>clk</sub> ÷ (OS × N) &nbsp;·&nbsp; error = (baud<sub>actual</sub> − baud) ÷ baud</p>

## Worked example

16 MHz clock, 115,200 baud, 16× oversampling:

- f ÷ (16 × 115,200) = 8.681 → N = **9** (UBRR = 8)
- Actual baud = 16,000,000 ÷ (16 × 9) = **111,111 bit/s**
- Error = **-3.55%** — too large; use 8× mode or a 11.0592 / 18.432 MHz crystal

## Notes

- Both ends contribute error — a ±2% error on each side can add up to 4%.
- RC oscillators (internal clocks) can themselves be ±1–2% off; use a crystal for high baud rates.

## Fixing the default example

With a 16 MHz clock, 115,200 baud and 16× oversampling the calculator gives N = **9**, an actual rate of **111,111 bit/s** and an error of **-3.55%**. Three ways to bring it down:

- **8× double speed mode:** N = round(16,000,000 ÷ (8 × 115,200)) = 17, so 117,647 bit/s and **+2.12%** (on AVR, set U2X and UBRR = 16)
- **Fractional divider:** a UART that divides in sixteenths uses 8.6875 instead of 9, giving 115,108 bit/s and **-0.080%**
- **Baud rate crystal:** 14.7456 MHz or 11.0592 MHz divides exactly, so the error is 0%

## How much error a receiver tolerates

The receiver syncs on the falling edge of the start bit and then samples each bit in its centre. In an 8-N-1 frame the last sample, in the stop bit, falls 9.5 bit times after that edge. The accumulated timing slip must stay under half a bit, less the uncertainty in detecting the start edge (one sample period). That gives a total budget of (0.5 − 1/16) ÷ 9.5 = **4.61%** with 16× oversampling and **3.95%** with 8×. The budget is shared by both ends, so a link where the transmitter is +2% and the receiver -2% is already at the edge. The default -3.55% error slips 0.35 of a bit by the stop bit, which leaves little margin for the other device's clock error.

## Measuring the real baud rate

Put an oscilloscope or logic analyser on the TX line and send the character 0x55 ('U'), which produces alternating bits. Measure the width of one bit: at 115,200 baud it should be 8.68 µs, while the default 16 MHz setting gives 9.00 µs. Measuring across all ten bits of the frame averages out trigger jitter and gives a more precise result.

## Common mistakes

- **Writing N into a register that expects N − 1.** AVR UBRR and many other dividers are offset by one, which shifts the rate by a whole step.
- **Using the core clock instead of the peripheral clock.** On many microcontrollers the UART runs from a prescaled bus clock, so the divisor is wrong by the prescaler ratio.
- **Trusting an internal RC oscillator at high baud rates.** Its own tolerance of 1% to 2% adds to the divisor error.
- **Checking only one end.** A PC USB adapter and a microcontroller each have errors, and only their difference matters.
- **Forgetting longer frames.** With 9 data bits or parity the stop bit sits later in the frame, so the allowed error is smaller.
